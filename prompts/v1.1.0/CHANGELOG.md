# 提示词与适配器 1.1.0

日期：2026-10-30。由用户明确的最小截图和数据边界驱动，未作真实 API 或手机验收。

基线为完整保留的 `../v1.0.0`；其方法修订 P01…P10 仍成立。原始交接材料未改动，本版不宣称与旧实验逐字或逐协议一致。

## 新增差异

| 编号 | 修订 | 含义 |
| --- | --- | --- |
| P11 | GUI 仅一张当前图片 | 旧图片与附图包装不进入阶段文本历史或后续请求；文本及原生工具消息配对保留 |
| P12 | Planner 仅必要边界图 | P1／P2 独立组装，不累积旧 API 图片；可选接管前帧、归还帧、最新查证帧按用途去重和释放 |
| P13 | 图片仅临时内存 | 不写文件、磁盘缓存、日志、导出、备份；从接管请求起停止采集，丢弃迟到截图 |
| P14 | 明确内容与日志隔离 | 任务、回复、提示词与工具参数仅运行时内存；持久化日志限结构化元数据；Key 本人本机加密保存 |

1.0.0 中 `automatic_history_truncation=false` 不再限制图片释放；1.1.0 改为 `automatic_text_history_truncation=false`。这是预先声明的图片保留策略，不是超限时的隐藏截断。

GUI 系统、阶段任务和共用归还通知均明确只有当前图；Planner 提示明确少量边界图与缺失证据。工具定义、Planner 四字段输出 Schema、坐标、PNG 格式、请求采样、预算及阶段分支不变。

P2 COMPLETE＋FINISH 仍直接由协调器结束，不新增 GUI done；P1 COMPLETE 仍要求其一轮只读确认。模型结束声明不成为成功标签。

详见当前补充规格与 `docs/DATA_AND_LOGGING_BOUNDARIES.md`；离线检查和未验证项目见 `VALIDATION.md`。
