先将 MH 控制条移到测试页下方静态区域，避免浮层实际遮挡可点击控件。开始任务后，开发驱动只使用 MH 的正常“接管”按钮发出一次接管请求；用户在人工阶段真实操作，再亲自使用 MH“归还控制”。没有向模型转述用户在聊天中确认的人工操作内容。

## 人工区间与计账

从接管请求开始到归还请求前，不调用布局／截图检查、不查询前台包名或焦点、不监听或读取人工输入。独立界面工具在发出接管前已退出，人工期间开发侧仅轮询本会话无内容的控制权及模型调用计数。用户的具体操作轨迹未采集、未写入结果或模型请求。

日志中人工就绪事件后紧接归还请求事件，没有新增模型调用或 Agent 动作，G=1、P=0 保持不变。GUI1 有唯一 cancelled 终态、耗时 1,923 ms，没有对应动作；归还后的 GUI 从第 2 步继续，因此取消没有退款，人工控制没有扣步或重置预算。

应用采集入口按现有控制权门控关闭，原观察回调通过代次检查失效。本轮未增加截图次数插桩；“没有新的模型调用”不能单独证明没有采集截图。该边界还依赖既有代码与本地可控设备测试，不能把本次最小日志冒充采集计数实测。

## Planner 与恢复执行

归还后的 P1 使用 6,964 ms 返回合法 `INCOMPLETE + EXECUTE`。随后 5 次 GUI 请求均记录为 RECOVERY，序号为 2～6，动作类型依次为 tap、tap、tap、long_press、finish，结果均 completed。交付后没有新增 Planner 调用，最后由 GUI 的 completed 声明结束。

共 26 条生产最小事件全部通过既有 minimal-event Schema，序号连续，每个模型 started 有且仅有一个终态；有效归还提交仅 1 次。没有模型／设备／协调器错误，没有代替用户填写任务结果评价。

只在归还已提交且流程已结束后进行界面核验，确认测试 App 为活动窗口，并在内存中检查：点击计数为 3、长按计数为 1，输入、保存状态及保存内容与开始前一致。所有布尔断言均通过，可确认可见计数目标与最终状态保持要求达成；结论独立于模型的完成声明。
