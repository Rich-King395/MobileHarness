## 截图／避让验证的方法和限制

Debug-only、DUMP 保护入口在原运行器 IDLE／ENDED 且没有 native input 时，临时接管自身服务的控制接口。它只在合成测试 App 前台取三张图：展开控件可见的原始截图 A、主动隐藏控件后的参考 B，以及实际生产 observe 返回的 C。截图调用预留至少 650 ms 间隔，无隐藏重试。

比较范围是展开控件内部，排除系统栏和外部阴影；RGB 通道差值容忍 4，A／B 至少 5% 样本改变才建立可见基线，B／C 改变不超过 0.1% 才通过。这里只保存比较结论，不保存图片、像素摘要、坐标或底层控件内容。

随后对 compact 控件原覆盖位置调用一次生产 tap，检查避让和终态。此检查没有断言底层业务控件被正确触发，不证明任意手势、任意 App 或模型任务成功。几何单测额外覆盖 tap、交叉／擦边、线段而非外接矩形、旋转／小屏、另一侧／另一高度避让，以及无安全位置时拒绝。

首轮 [attempt 1](results/pixel4-overlay-0.2.0-attempt1.json) 为 FAIL：验证器在假 AUTO 状态下人为隐藏入口，触发了生产的“停止入口丢失”保护。修正 debug 参考阶段为内部 IDLE（从未进入 MANUAL）后，[attempt 2](results/pixel4-overlay-0.2.0-attempt2.json) 通过，耗时 3.769 秒，GUI／Planner 均为 0，真实 perform 为 1。首轮失败保留，不计为模型或任务能力问题。

修复主页面状态订阅后，最终安装包上的 [再次检查](results/pixel4-overlay-0.2.0-final.json) 也通过，耗时 3.571 秒，GUI／Planner 均为 0、真实 perform 为 1。本轮这些 debug 检查合计 0 次模型调用、2 次真实 perform；不隐藏首轮失败或合并成一次尝试。

## 主页面状态订阅

设备首次打开主页面时显示“悬浮控制入口尚不可用”。只读 debug 广播保持 Main 前台，确认真实 service readiness、panel available／installed、root shown／visible 都为 true，见 [修复前诊断](results/pixel4-ui-readiness-before-fix-0.2.0.json)。因此该问题是主页面状态订阅滞后，并非已证实的窗口挂载失败。

修复为由 Application 发布服务连接身份，Main 跟随身份切换 readiness Flow；新服务晚于首次组合绑定时，也能自动刷新。旧连接的 detach 仍由 PhoneBridge 身份检查拒绝，避免清除新连接。

最终覆盖安装后，不切换页面，界面已显示连接且没有入口不可用警告，开始入口可见。只读诊断也确认实际就绪，见 [修复后诊断](results/pixel4-ui-readiness-after-fix-0.2.0.json)。两个诊断文件的 PASS 仅表示固定旗标采样完成；主界面提示是否正确由另外的 UI 检查确认。
