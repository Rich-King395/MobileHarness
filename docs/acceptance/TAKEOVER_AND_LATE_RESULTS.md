## 层级、记号与取证范围

| 层级 | 后续验证对象 | 本文件中的限制 |
| --- | --- | --- |
| C：协调器替身 | 可控事件调度、虚拟时钟、模型／截图／执行器替身、内存状态 | 不发真实 HTTP、不执行手机输入；替身的请求尝试计数对应运行时实际请求的计步语义 |
| A：请求组装 | 合成图片与文本、原生工具消息关联、将发出的请求对象 | 仅检查内存对象；不请求模型；不保存请求体、图片或截图哈希 |
| D：真机 | 后续最小 APK、已授权测试设备、专用测试 App、可控结果注入 | 仅使用授权 sandbox 和合成内容；设备日志仍遵守白名单，不调用真实用户任务或商业模型接口 |

P0 表示违反后会导致失控操作、错误交接、额度错误或内容采集越界；P1 表示次要诊断或表现问题。本组均为 P0 核心场景。列出的 C／A／D 均须分别验收，不能以 C 通过代替真机通过。真实平台无法稳定制造的回调顺序，应通过后续测试替身／回调门控复现，标明注入层级，不声称它等于平台已经实际发生该故障。

- `T`：当前任务；`E0`：接管前控制权代次；`E1`：接管后使旧工作失效的新代次。它们是测试记号，不规定生产字段格式或每次加一的实现。
- `R0`：接管前已发出的模型请求；`R1`：归还后合法的新请求；`I0`：执行器已登记、仍未结算的输入。
- `G/P`：已计入的 GUI／Planner HTTP 尝试数；`D`：自动输入派发数；`O`：截图采集启动数；`U`：本任务已提交的接管／归还轮次数。`D/O/U` 仅为瞬态测试 oracle，不新增到生产日志 Schema。
- 每例的 `g/p/d/o` 基线在其前置事件完成后读取。前置中已发出的 `R0` 已经消耗一次额度；后续取消、丢弃或终态不退还、也不再次扣同一次请求。
- 需要合法新请求的场景预留相应 GUI／Planner 额度，所有前置均遵守一次接管及两次规划上限；额度耗尽不是这些成功归还分支的隐含前置。
- 有效历史指后续实际模型输入可读取的文本／工具会话及 Planner 自身成功动作历史，不包括隔离的解析候选。旧结果不得通过错误文本、诊断摘要或补写工具消息进入有效历史。
- C 的事件序在串行协调器入口与“最终派发前”检查点精确调度。仅在同一合法运行轨迹的边界注入竞态，不为制造场景而建立本产品不允许的并发执行路径。

测试期间不采集人工画面、触摸／输入轨迹、UI 节点快照或窗口变化序列。D 的人工阶段仅观察本应用的控制状态和采集入口计数，不录屏、不截屏来证明用户做了什么。合成标记、回调归属、候选历史和内存槽等 oracle 只在测试进程内使用，用后释放；不得将用户内容写入额外测试文件或崩溃附件。持久结果只写 Case ID、层级、通过／失败／未执行和无内容原因码，运行日志仍仅使用已有白名单。

## CT-01：等待 GUI 时接管，不等待 HTTP 取消确认

**优先级／层级／状态：P0；C、D；待实现，未执行。**

**前置：** `AUTO`，首次接管尚未使用，`R0` 已发送且 `G=g>=1`、`P=p`；没有已提交输入，也没有待提交动作。替身故意不返回 HTTP 取消确认。记录 `D=d/O=o/U=0`。

**精确事件序：**

1. 当前任务、代次和状态均有效的接管事件进入协调器。
2. 协调器关闭输入与观察入口、使 `E0` 工作失效，并取消尚未开始的队列／定时工作。
3. 验证没有在途输入，完成本地暂停屏障；HTTP 请求仍处于未确认取消状态。
4. 保持远端／替身请求未结束，推进事件队列，不触发归还。

**Then：**

- 进入 `MANUAL`，`manual_granted` 恰好一次；悬浮条与可用通知入口显示同一状态。无须等满 5 秒或等 HTTP 取消确认。
- `G=g/P=p/D=d/O=o/U=0`。人工时间、控制事件与本地取消都不产生模型步骤。
- 不再发新模型请求、采图或输入；不伪造 `R0` 已成功、已执行或已退款。对方已收到的请求不能被宣称撤回。

## CT-02：旧模型结果在四个时点到达，均不能重新生效

**优先级／层级／状态：P0；C、A、D；待实现，未执行。**

**前置：** 接管前已发出 `R0(T,E0)`，随后发生有效接管。分别运行 Harness 开／关。旧响应使用三个独立合成载荷：一个合法 `tap`、一个 `finish(completed)`、一个 `finish(unable)`；均保留真实协议形状，但不含用户数据。

**精确事件序：** 每次只选择下列一个到达时点；在该检查点投递一次旧响应，再重复投递同一回调。其他新请求保持未完成，以隔离旧响应效果。

| 到达时点 | 精确调度位置 |
| --- | --- |
| 暂停中 | 派发门已关闭且代次已失效，但 `manual_granted` 尚未发出的屏障检查点；若实现不暴露此间隙，C 门控该检查点，D 只标记回调已在该时段入队 |
| 人工控制 | `manual_granted` 已成立，尚未请求归还 |
| 归还之后、新请求之前 | 归还检查与新观察已有效、`return_committed` 已提交，模型发送检查点尚未放行 |
| 新请求之后 | Harness 关：新 GUI 请求 `R1` 已发送；Harness 开：P1 已合法交付 `EXECUTE` 且新 GUI 请求 `R1` 已发送；均先扣额度再投递旧响应 |

**Then：**

- 旧响应及重复回调带来的增量均为 `ΔG=ΔP=ΔD=ΔO=ΔU=0`，不改变当前有效阶段、目标或结束状态，不触发新查证、重规划或归还。
- `R0` 的 assistant、tool call ID、正文、finish 消息及任何派生摘要都不进入有效历史；A 检查下次请求对象中没有这些合成旧结果。原任务原文和原有合法文本历史不因此被清空。
- 新请求之前的总量仅包括前置合法工作；新请求之后以其已计账值为基线。若归还后只发了 P1 和一个新 GUI 请求，Harness 开为 `G=g+1/P=p+1`，关为 `G=g+1/P=p`；旧回调不能改变该值。
- 同一次模型尝试最多一个终结日志。若取消已记为 `cancelled`，后续迟到回调不得再补第二个终结事件；否则可按实际情况终结为 `late_discarded`。不得为旧回复写动作成功或会话成功记录。

## CT-03：响应先被解析，接管抢在最终派发之前

**优先级／层级／状态：P0；C、A、D；待实现，未执行。**

**前置：** `R0(T,E0)` 已计入 `G=g`。合法 `tap` 响应已完成解析与参数校验，候选动作被停在最终派发检查点；尚未调用手机执行接口。无其他在途输入，`D=d/O=o`。

**精确事件序：**

1. 先处理有效接管事件，关闭派发门并使 `E0` 失效。
2. 释放先前解析候选的派发检查点，让它尝试继续。
3. 达成本地屏障并进入人工；随后合法归还，检查新请求的历史输入。

**Then：**

- 候选在最终检查处被拒绝，`D=d`；解析成功不能绕过 task／phase／epoch／frame 与派发门的最终检查。
- 接管自身 `ΔG=ΔP=ΔO=0`，无 HTTP 取消等待；`manual_granted` 恰好一次。
- 候选不成为后续可执行指令、Planner 成功动作或有效历史中的未配对 tool call。若实现曾把候选放进临时解析缓冲，须在归还后的请求组装中确认它仍被隔离。
- `R0` 若已完成并记为模型调用 `succeeded`，该元数据不等于动作已执行；不允许补造动作完成或业务成功。此例不要求改写已发生的真实调用记录。

## CT-04：已派发手势必须收到终态，取消协程不等于结算

**优先级／层级／状态：P0；C、D；待实现，未执行。**

**前置：** `AUTO`，`I0` 已调用 `dispatchGesture` 并返回 `true`，但完成／取消回调尚未到达。该次派发已包含在 `D=d`，模型请求已包含在 `G=g`。分别测试完成与取消两种终态。

**精确事件序：**

1. 接管事件生效，关闭派发和采集，取消协程及待提交队列。
2. 先交付 HTTP 取消确认或本地队列清空确认，暂不交付 `I0` 终态。
3. 检查状态仍为 `PAUSING`，归还按钮不开放。
4. 交付匹配已登记 `I0` 的 `onCompleted` 或 `onCancelled`，确认无其他继续注入输入的操作。
5. 重复交付同一终态。

**Then：**

- 只有第 4 步之后才进入 `MANUAL`，`manual_granted` 总数为 1；重复回调不再迁移状态。
- 全序列 `ΔG=ΔP=ΔD=ΔO=0`；原手势结果只结算一次，取消不退款。
- 仍登记为在途的旧输入终态可用于关闭屏障；这不使同代次的旧模型响应或旧截图重新有效。
- 不派发另一手势来“强制取消”，不回滚已发生的修改，不以业务页面静止或后台保存结束作为屏障条件。D 不阻止用户提前触摸，也不记录其触摸；只能显示等待交接确认。

## CT-05：5 秒只进入暂停未确认，不自动授予人工控制

**优先级／层级／状态：P0；C、D；待实现，未执行。**

**前置：** CT-04 的 `I0` 终态被门控，接管事件时刻为虚拟 `t=0`，当前有效意图仍是接管。D 后续通过测试回调门控延迟终态，不制造超出工具契约的超长手势。

**精确事件序：**

1. 推进至 `t=4999ms`，不给终态。
2. 推进至 `t=5000ms` 并处理异常提示定时事件。
3. 再推进时间并重复执行“重新检查暂停”，仍不给终态。
4. 最后交付匹配 `I0` 的完成／取消终态，重新确认屏障。

**Then：**

- 第 1 步仍为 `PAUSING`；第 2、3 步为 `UNCERTAIN`，`manual_granted=0`，归还入口不可用。
- 派发门和观察入口持续关闭；计数 `G/P/D/O/U` 不变。重复检查不会补发输入、截图或模型请求，不会重置 5 秒后自动交接。
- 只有第 4 步满足屏障后才允许一次 `manual_granted`。超时不是人工控制，也不是动作已取消、设备问题已消失或任务成功的证据。
- 最小日志可记录已有 `pause_unconfirmed` 控制事件及固定错误码，不附输入内容、屏幕信息或原始异常文本；重复提示的去重频率不在本例另设新产品规则。

## CT-06：暂停中改为停止，迟到回调不能短暂开放归还

**优先级／层级／状态：P0；C、D；待实现，未执行。**

**前置：** 有未结算 `I0`，首次接管已进入 `PAUSING` 或 `UNCERTAIN`，尚无 `manual_granted`。分别运行这两个起始状态。

**精确事件序：**

1. 处理当前任务的停止请求，将有效意图改为停止；不重新打开派发门。
2. 在终态到达前，投递旧模型响应、旧截图及原暂停检查回调。
3. 交付匹配 `I0` 的完成／取消终态，确认停止屏障成立。
4. 再次投递上述旧回调和旧通知的归还动作。

**Then：**

- 屏障成立前仍显示停止处理中或尚未确认；成立后进入 `ENDED` 的已停止结果。
- 整条状态轨迹中 `manual_granted=0/return_committed=0`，归还按钮从未短暂可用。旧暂停意图不能覆盖较新的停止意图。
- `ΔG=ΔP=ΔD=ΔO=ΔU=0`；旧回调不能使任务进入 `MANUAL/PREPARING/AUTO/CHECKING`，也不能重新打开观察入口。
- 只结算实际已发送尝试及实际在途动作；结束原因是用户停止，不伪造模型完成、任务成功或额外 GUI finish。

## CT-07：暂停后迟到截图丢弃，人工不采集，归还取得新图

**优先级／层级／状态：P0；C、A、D；待实现，未执行。**

**前置：** 一个截图请求 `C_old(T,E0)` 在接管前已经启动，但未返回。可另有一张接管请求前已取得的 `F_pre`；有／无 `F_pre` 分别测试。所有替身图片使用不同的合成内存标记，不使用真实人工画面。

**精确事件序：**

1. 处理接管并停止采集。分别在 `PAUSING`、`MANUAL`、归还后新图已有效这三个时点交付 `C_old` 的回调。
2. 人工阶段推进时钟，并向必要无障碍事件入口注入不读取内容的合成事件。D 可由本人在授权 sandbox 自由操作，但不记录操作过程。
3. 用户请求归还；解锁、授权和执行器检查通过后，启动一次新采集 `C_return`。
4. 交付新的 `F_return`，检查将发出的 GUI 或 P1 请求；此后结束本轮恢复准备，检查边界槽释放。

**Then：**

- `C_old` 的结果直接丢弃并释放，不进入 GUI、Planner、有效历史、日志或临时边界槽；不能冒充 `F_pre` 或替换更晚的 `F_return`。
- 自接管事件生效起至有效归还检查通过前，新增采集启动数为 0。系统仍可能回调无障碍事件；内容不被读取成轨迹、节点快照或窗口序列，人工操作不改变 `G/P`。
- 此例仅计归还新采集时 `ΔO=1`；采图本身不扣 GUI／Planner 步数。模型发送检查点放行前 `ΔG=ΔP=0`，实际放行哪一角色才计该角色一次。
- A：GUI 请求恰好一张 `F_return`；Harness 开时 P1 只附 `F_return` 与仍必要且在接管前已取得的 `F_pre`，缺失时 `pre_handoff_frame_id=null`。Harness 关不保留 Planner 专用帧。不得附人工图片、迟到旧图、旧图片包装文字或旧 Base64。
- 恢复准备结束即清理无用途边界槽；使用 A／内存 oracle 验证引用归属，不记录图片哈希，不宣称运行时物理副本能立即全部擦除。
- 补充失败变体：归还前置检查失败时 `ΔO=ΔG=ΔP=ΔU=0`；新采集失败时 `ΔO=1/ΔG=ΔP=ΔU=0`，回到 `MANUAL` 并保留归还机会。修复后的显式重试必须再取新图，不能复用失败或迟到结果，也不能因此增加接管轮次。

## CT-08：队列和 wait 定时回调不能绕过失效代次

**优先级／层级／状态：P0；C、D；待实现，未执行。**

**前置：** 分别运行两个独立合法轨迹：A 为一个尚未提交的本地动作候选；B 为一个已经计入 GUI 额度、等待 1000ms 后刷新画面的 `wait`。不同时制造多个模型工具调用。无已提交输入。

**精确事件序：**

1. 在动作提交或 wait 到期之前处理接管，取消待执行工作并使其代次失效；屏障成立后进入人工。
2. 强制交付原队列运行回调／wait 到期回调一次，再交付一次重复回调。
3. 合法归还并建立新工作后，再投递同一旧回调；以新工作已经产生的计数为新基线。

**Then：**

- 每次旧回调均造成 `ΔG=ΔP=ΔD=ΔO=ΔU=0`，不发新的画面、下一轮 GUI、Planner 或动作；wait 已消耗的一步不退款，也不再扣一次。
- 已关闭的派发／观察入口不会被旧回调重开；旧 wait 不阻碍本来无在途输入的人工交接，也不被误当作归还后的刷新结果。
- 如该操作需要终结元数据，只结算原操作一次；不得写成新的自动输入成功、人工操作或新的会话。重复回调不补造配对 tool 消息进入有效历史。

## CT-09：旧通知与重复点击只允许至多一次有效归还

**优先级／层级／状态：P0；C、A、D；待实现，未执行。**

**前置：** `T1` 已安全进入 `MANUAL`、`U=0`。保留合成旧动作：其他任务 `T0`、失效代次以及当前任务／代次但当前状态不允许的动作。当前合法归还动作可从通知或悬浮条进入同一事件入口。D 须先确认通知权限及渠道有效；否则通知子项保持未执行，不能用系统 Task Manager 冒充通过。

**精确事件序：**

1. 投递 `T0`、失效代次和状态不匹配的归还动作，检查均无副作用。
2. 连续投递两次当前有效归还；把第一次归还的新截图回调暂扣在检查点。
3. 再投递通知／悬浮条的重复归还，随后交付第一次有效新截图。
4. 提交本轮归还并放行后续发送：Harness 关仅发一个新 GUI 请求；Harness 开先发一次 P1 并暂扣其结果。
5. 再投递全部旧动作，包括当前任务上前一状态的合法归还 token。

**Then：**

- 单次有效流程最多启动一份归还取图，`ΔO=1`；`return_committed=1/U=1`，没有并行恢复流程。
- Harness 关：`ΔG=1/ΔP=0`；Harness 开：在 P1 结果门控时 `ΔG=0/ΔP=1`。重复点击不消耗额外模型额度，不重置预算或 Planner 两次上限。
- 旧任务／旧代次动作不能迁移当前任务；重复点击不能使状态倒退 `MANUAL` 再归还，也不产生第二个 `return_committed`。
- A：Harness 关的继续请求不因重复点击而重复注入归还通知或新图；Harness 开的 P1 只组装一次，不要求 Planner 输入包含 GUI 归还通知文本。均不注入旧任务文本或旧通知内容。通知与悬浮条触发同一屏障，二者不能各自提交一次归还。
- 持久日志只保留实际有效控制转换和白名单元数据。被拒绝通知的 task／epoch 内容可在瞬态 oracle 中核对，不新增到导出字段。

## CT-10：已用完一轮后仍可停止并手动继续，但不能第二次归还

**优先级／层级／状态：P0；C、D；待实现，未执行。**

**前置：** 本任务已经提交过一轮有效归还，`U=1`，目前在 `AUTO`；分别设置为无在途输入与有 `I0` 两种情况。`G=g/P=p/D=d/O=o`。保留首轮人工阶段的旧归还通知和旧回调。
