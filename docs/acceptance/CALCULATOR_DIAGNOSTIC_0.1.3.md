## R-05：一次落点与实际效果核验

为区分视觉落点和设备派发问题，在 0.1.3-dev debug 包增加由系统 DUMP 权限保护的独立入口。仅当计算器当前算式为空时进行一次 GUI 请求，目标是点击数字 2。使用同一 v1.1.0 ORIGINAL 原生执行工具，模型只看到当前截图和合成目标，不获得本地节点边界或隐藏评分。

本地仅在内存中比较模型原始归一化落点与数字 2 的可见节点区域。未命中时报告 GROUNDING_MISS 且不执行；命中时将原 action 对象直接交给真实执行器，不能代换为节点中心，也不改写坐标或重试。随后独立检查当前算式是否为 2。该额外合成目标检查仅存在于 debug 诊断，不接入正常 Agent 或 Harness 的结束门槛。

本次 **PASS**：[记录](results/pixel4-calculator-point-0.1.3.json)。耗时 5,027 ms，GUI 1、Planner 0、真实 perform 1；模型输出为 tap，落点命中数字 2，原生输入完成，当前算式为 2，真实终态已确认且原控制器已恢复。元数据没有坐标、算式原文、截图、模型回复或 Key。临时 REPORT_VIEW_IDS 标志结束后恢复，没有改生产无障碍配置。

这仅证明本次单步的落点、坐标换算与派发效果有效。R-04 的任务终态仍为未达成，不能用 R-05 改写历史结果，也不能据此断定 R-04 全部 APK 合同正确。后续只补 APK 输入／执行保真与控制流程的必要验证，不再将改善模型多步动作选择、计算能力或推理提示词作为本项目的优化目标。

## “没有看到操作”的解释边界

正常执行在目标 App 的真实前台界面进行，没有另一个 Agent 视频窗口。当前没有鼠标或点击位置标记；文字输入通过一次 ACTION_SET_TEXT 完整替换。R-02 在首个 GUI 请求返回前接管，接管前没有动作是预期，恢复动作发生在归还之后。

如果目标 App 始终不出现，或页面完全没有变化，需要检查启动、暂停和模型／执行链路，不能只用“缺少动画”解释。运行时重新打开 MobileHarness 会按安全策略接管或停止；用户应在目标 App 观察，并通过 MH 查看状态。本次计算器有真实可见变化，但未达到计算目标，二者分别记录。
