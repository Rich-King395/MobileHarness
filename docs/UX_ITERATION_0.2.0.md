# MobileHarness 0.2.0：日常任务与悬浮控制

记录日期：2026-10-31。版本：0.2.0-dev（versionCode 5）。本轮只改进 APK 界面和控制入口，不调整模型提示词、任务目标、动作坐标约定、采样参数或 Harness 规划／预算规则。

## 交互目标

任务输入是主页面的中心。授权 App、初始 App、Harness 与预算以清楚的摘要和按需展开的设置呈现。借鉴移动端对话应用的留白、输入区和底部面板，不复制品牌，也不把不保存的任务正文伪装成可恢复的聊天记录。

远端截图发送说明和用户主动同意仍是启动条件。GUI／Planner 各自的接收者可以查看，密钥仍只在手机本地加密保存。草稿只在内存中保留；只有启动成功后才清除，进程退出后不恢复自动任务。

悬浮入口默认贴边收起，可拖动并吸附左右侧。自动操作时保留独立停止触点；需要接管、归还或处理问题时再展开。接管后的“暂停中”仍须等待输入终态，之后才显示“人工控制”。

任何可触摸的悬浮控件都占用少量屏幕区域，不能保证完全不遮挡。运行中若原动作路径与自家控件相交，只移动自家控件，等待两帧，再检查控制权、屏幕几何、授权 App 与实际冲突，然后按模型原坐标执行。没有安全位置时明确报告设备执行问题，不修改模型动作。

截图前隐藏整个悬浮窗口，等待两帧后调用原截图入口；截图后恢复收起状态。不会以裁图、涂抹、坐标平移或在图片上添加点击标记来消除控件。

## 验证记录

已构建、签名校验并覆盖安装到 Pixel 4，保留本机模型配置与加密密钥。50 项 JVM 测试通过；空任务、已选 App 和暗色任务页已离线渲染并查看。

真机检查通过：任务框、App 搜索框及预算框在键盘上方；App 搜索／授权／初始选择摘要正常；内存草稿切换页面后保留；发送同意默认未勾选，开始入口首屏可见。修复了服务晚绑定时主页面仍订阅空 readiness Flow、错误显示悬浮入口不可用的问题。最终安装后无需切换页面，就绪提示自动更新。

最终 APK 上的零模型截图／输入检查通过：可见控件基线成立，生产截图匹配隐藏参考，截图后恢复 compact，原覆盖位置的真实 tap 完成避让、原参数保持不变并确认 native 输入终态。首轮验证器自身的隐藏时序错误及失败记录保留。方法、阈值与覆盖限制见 [验收记录](acceptance/UI_AND_OVERLAY_0.2.0.md)。

本轮不调用商业模型，不评价模型推理能力。设备测试只使用授权合成页面；截图在 RAM 中比较并释放，只保留无内容结论。旧提示词包及交接材料维持冻结。

界面与悬浮入口可能影响人的接管时机，因此 User Study 前需要固定使用的 APK 版本，并在 Harness 开关组采用一致界面。

本次没有重新执行真人接管实验或完整的 37 个 Harness 主场景。实际旋转、大字号、长任务和不同 App 组合仍待后续逐项验收。
