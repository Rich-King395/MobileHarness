# 0.5.0 执行反馈补充规格

日期：2026-11-02。适用于 MobileHarness 0.5.0-dev。用户已明确要求：可恢复的手机动作失败应交回 GUI Agent 重新观察和决策，避免每次都等待用户手动修复。本文件记录这项方法增量；验收结果另行记录。

## 版本与适用范围

| 条件 | 当前值 | 含义 |
| --- | --- | --- |
| 自动桌面模式提示词包 | 1.2.0 | 冻结资源及其继承关系不变 |
| 自动桌面模式适配器 | 1.4.0 | 沿用 1.3.0 的合法原生工具调用附带文字接受规则，加入固定执行失败反馈 |
| 旧指定 App 模式提示词包／回复解析 | 1.1.0／1.1.0 | 保留原回复封装校验；执行反馈由独立执行策略版本标记 |
| 执行策略 | 1.1.0 | 明确终止且可恢复的动作失败可触发新的 GUI 判断 |
| 新会话最小日志 Schema | 1.2.0 | 增加执行策略版本及可选固定执行原因 |

`SessionOptions` 决定运行时适配器及执行策略版本。冻结 `request-profiles.json`、manifest 中的旧版本标识继续作为原快照保留，不把它们改写成新运行器版本。新会话在 `session_started` 分别记录 `prompt_bundle_version`、`adapter_version` 与 `execution_policy_version`。

旧指定 App 模式的适配器编号 1.1.0 仅说明其原回复解析仍严格执行，不表示整个运行行为等同于旧实验：它也记录并使用执行策略 1.1.0。

## 明确动作失败后的处理

仅在以下条件同时成立时，协调器自动继续：

- 当前仍在有效的同一会话、阶段和控制权代次，未收到接管或停止请求。
- 当前阶段为 `ORIGINAL` 或 `RECOVERY`，手机连接有效，没有尚未确认终态的输入。
- 执行结果为 `device_error`、`cancelled` 或 `rejected`，且带有明确标为可重新观察的固定原因。
- 对应错误属于 `DEVICE`，错误码为 `INPUT_FAILED` 或 `SCREENSHOT_FAILED`。

协调器保留本次原始工具调用和失败结果，记录无内容错误元数据，然后重新获取当前画面，向 GUI Agent 发起下一次请求。模型根据新画面、同阶段历史和固定原因自行选择下一动作。不会自动再次执行刚才的动作，不会替换 Enter、猜测文本框、修改输入文字或修正模型落点。

系统返回失败或取消，不一定表示屏幕完全没有变化。例如取消的手势可能已产生部分效果，文字写入或导航返回失败也不能证明界面未变。固定反馈说明这种不确定的可见效果；模型需要查看新图，执行器不能把它当成“可以原样重放”的依据。

本次失败不修改原任务、恢复目标、阶段或历史边界，不额外调用 Planner，不开始新的查证轮次，也不进入持续重规划。仅观察／等待的 `VERIFY`、`CONFIRM` 仍按原只读规则处理；获取画面失败不会借本策略获得导航或写操作能力。

## 固定反馈与历史隔离

GUI 工具结果继续使用原结构：

```json
{"execution_status":"device_error","message":"<fixed execution feedback>"}
```

存在 `failureReason` 时，`message` 取本地枚举内固定的英文反馈，不使用动态异常正文、屏幕文字、控件属性、包名、输入值或密钥。没有分类原因的结果保留既有结构，正常结果的空 `message` 不变。原工具名称、call id、参数 JSON、图片、坐标范围与结束声明仍按原协议处理；不把反馈扩展成新的模型动作格式。

失败动作属于 GUI Agent 自身本阶段的尝试，因此可留在该阶段文本历史中。它不进入 Planner 的 `own_action_history`；Planner 继续只接收 Agent 自身执行完成的有效动作，`finish` 声明也不作为完成的手机动作。阶段切换仍新建 `VERIFY`、`CONFIRM`、`RECOVERY` 对话；`FALLBACK` 恢复原任务历史并从当前画面继续，不撤销人工操作。

Harness 开启与关闭共用本执行策略和固定反馈。关闭模式在归还后仍使用原任务、自身历史和新画面直接继续，不进行 Planner 调用、阶段历史切换或剩余目标注入。失败反馈不是 Harness 专用的额外信息。

## 原因闭集

下表是本版本的固定分类；每项对应源码枚举中的固定英文反馈，不拼接运行时内容。

| 原因 | 允许模型重新观察后选择下一步 | 分类含义 |
| --- | --- | --- |
| `NO_FOCUSED_INPUT` | 是 | 没有获得输入焦点的输入框 |
| `INPUT_NOT_FOCUSED` | 是 | 输入目标未同时满足可见和已聚焦条件 |
| `INPUT_NOT_EDITABLE` | 是 | 焦点元素不可编辑 |
| `INPUT_DISABLED` | 是 | 焦点输入框未启用 |
| `INPUT_ACTION_UNSUPPORTED` | 是 | 输入框不支持当前文字写入动作 |
| `SET_TEXT_REJECTED` | 是 | 文字操作返回失败，可见效果未确认 |
| `IME_SUBMIT_UNSUPPORTED` | 是 | 没有可验证的 IME 提交能力，未执行 Enter |
| `GLOBAL_ACTION_REJECTED` | 是 | 系统导航操作返回失败，可见效果未确认 |
| `GESTURE_NOT_DISPATCHED` | 是 | 系统没有接受手势派发 |
| `GESTURE_CANCELLED` | 是 | 手势已收到取消终态，可能有部分效果 |
| `STALE_OBSERVATION` | 是 | 派发前发现观察已过期，拒绝原提议 |
| `OVERLAY_TARGET_BLOCKED` | 是 | 自家悬浮控件无法移开原动作路径，未改原坐标 |
| `PROTECTED_INPUT` | 否 | 输入目标受保护 |
| `INPUT_APP_NOT_AUTHORIZED` | 否 | 输入目标不在已有授权范围 |
| `CONTROL_NOT_AVAILABLE` | 否 | 控制权或必要控制入口不可用 |
| `DEVICE_NOT_READY` | 否 | 设备不满足授权自动操作的就绪条件 |
| `SCREENSHOT_UNAVAILABLE` | 否 | 无法获得授权的当前观察 |
| `INPUT_RESULT_UNKNOWN` | 否 | 输入结果或终态不确定 |

“是”还必须满足前述协调器条件，不意味着任何情况下都可以自动继续。未分类的执行异常也不能按可恢复失败放行。

## 预算、暂停与控制权

失败对应的 GUI 请求已占用一步，不退还。后续每次实际新请求继续扣共享 GUI 额度；人工操作不扣步、不重置预算，Planner 调用另计。没有剩余额度时直接结束自动流程，不为失败额外赠送一步。只读阶段最后一步未产生合法 `finish` 就耗尽额度时，仍不调用第二次 Planner；合法 P2 入口及其直接结束规则不变。

本策略没有为 HTTP 请求、模型格式错误或未知输入结果增加自动重试。模型 API 拒绝、传输或协议错误、服务断连、保护输入、授权／控制权不可用、当前观察不可用等仍进入原故障处理；HTTP 400 的具体原因须单独诊断，不能仅凭状态码认定为暂时网络问题或模型决策错误。

接管／停止请求仍优先于新观察和新派发。接管使旧代次失效，迟到回复不得执行；当前输入必须达到真实终态才能进入人工控制。未确认输入终态时仍保留“暂停未确认”屏障。人工期间不读取画面、窗口、节点或操作轨迹；归还重新获取画面。这些边界不会被自动继续路径绕过。

## 日志与实验可比性

新日志使用 [Schema 1.2.0](data-contracts/minimal-event.v1.2.schema.json)，补充说明见 [日志版本说明](data-contracts/README.v1.2.md)。`action` 在非 `completed` 结果时可记录固定 `execution_failure_reason`；`error` 仅在 `DEVICE` 分类时可记录该字段。普通日志继续不保存参数、正文、坐标、图片、Key、服务地址或目标 App 身份。历史 1.0.0／1.1.0 事件及进程中断补尾沿用所属版本，不追溯补推具体原因。

截图仍仅在内存中供当前 GUI 或必要 Planner 判断，不保留截图历史；新画面遵守原采集授权与悬浮控件隐藏规则。失败分类不是新增采集用户信息的理由。

这项改动改变了模型所收到的失败信息和自动继续条件，后续分析应同时区分适配器、执行策略及提示词版本，不能宣称与旧实验完全一致。旧提示词、交接材料、原方法快照和旧失败记录保留。模型声明结束、自动流程结束与任务成功仍分别记录和判断。
