# 实验记录与分析：0.9.0

日期：2026-11-03。`0.9.0-dev / versionCode 21` 已安装。本轮完善本机记录阅读、历史任务补评、描述性统计及无内容 CSV 导出；验收结果见 [summary.json](acceptance/results/experiment-analysis-0.9.0/summary.json)。冻结的 [0.8.1 基线](../baselines/2026-11-03-mobileharness-0.8.1/README.md)与旧提示词、历史验收原文继续保留。

## 手机上的使用

1. 打开“记录”，按 Harness 开关、评价等条件筛选。记录每页 10 条，可翻页查看。
2. 展开某条记录，查看原任务、共享 GUI 用量、Planner 调用、结束原因、用户评价、耗时及已有错误明细。历史任务也可补充或修改“已完成／未完成”评价，最新有效评价用于分析。
3. 未勾选记录时，分析范围为当前筛选结果中的全部已结束记录；勾选后，分析范围为所选已结束记录。分析不受当前显示页的 10 条限制，活动记录不进入已结束任务统计。
4. 选择需要导出的已结束记录，再导出 45 列分析 CSV，或继续使用原无内容 JSONL 日志。未选择时导出按钮不可用；空选择不会被解释为全部记录。

补评按 session ID 写入对应记录，不再依赖它是否是当前运行会话，也不改变另一任务的审计会话或序号。补评保持该记录原来的事件 Schema；不会延长原任务耗时、重新运行任务或把评价交给模型。

## 指标的含义

| 指标 | 本版口径 |
| --- | --- |
| GUI 使用步数 | 沿用共享预算计账，失败、取消、等待和结束声明仍按既有规则消耗；不等同于成功点击数 |
| Planner 调用 | 按实际调用索引配对 started 与终态，不把两条日志算成两次调用；决策与调用状态分开显示 |
| 模型有效回复 | 表示通过协议与回复处理，不表示模型选对了操作，也不表示任务成功 |
| 用户完成率 | 用户报告完成数 ÷ 已评价任务数；未评价单列，无已评价任务时保持未知，不显示为 0% |
| 模型结束与用户评价 | 模型声明结束、模型无法继续、用户停止、额度耗尽、运行故障等结束原因，与用户的完成／未完成评价分别保留 |
| 任务耗时 | 可确认的 session start 到 end 相对时长，包含人工控制及其他等待；不是纯模型推理时间 |
| 中断记录耗时 | `duration_ms` 保持未知；可用的 `recorded_duration_ms` 只是最后记录到的时长下界，不能代替实际中断时间 |
| 接管与归还 | 分别统计实际授予人工控制、成功提交归还的事件；本版不计算人工控制总时长，不重建人工操作轨迹 |
| 调用耗时 | 按有记录的调用终态汇总，并保留有效样本数；缺失值不补零 |
| 错误 | 展示请求／协议、设备执行、协调器等已记录环节及固定错误明细，不自动判为模型推理错误或 APK 根因 |
| 配置引用 | 记录中的不透明配置版本 ID，不是模型名称或模型权重；修改并保存配置可能生成新版本 ID，不能用当前名称回填历史事实 |

失败调用按角色与调用索引配对。接管引起的取消、迟到回复丢弃与模型失败分开统计。错误事件数和失败调用数也是不同指标：同一次请求问题可能同时留下二者，不能直接相加为“故障总数”。均值仅使用有记录的数值并保留样本数，旧记录缺失字段保持未知。

Harness ON／OFF 分组是描述性汇总。不同任务、配置版本、预算或提示词条件可能不同，不能仅凭完成率、平均步数或耗时差异推断 Harness 的因果效果。CSV 保留已有的版本和配置引用，便于后续按可比条件筛选；它不补造旧记录没有保存的运行版本或模型信息。

## 数据与导出边界

分析 CSV 采用独立的 `analysis_version = 1.0.0`，每条已结束记录一行，共 45 列。它由现有无内容元数据派生，包含用量、评价、时长、调用统计、固定错误摘要和已有版本引用；不是原始事件或任意 `data` 对象的转储。未知值导出为空单元格，不写成零或字符串 `unknown`。

- 原任务仍按 [0.7.0 约定](EXPERIMENT_RECORDS_0.7.0.md)以本机加密附件保存，供用户在记录中查看，不进入 CSV 或无内容 JSONL 导出。分析与 CSV 不依赖任务附件解密。
- API Key 只供本机正常调用使用，不进入记录附件、统计或导出。截图、原始模型回复、动作参数、人工画面与人工轨迹不因本功能而新增保留。
- 用户评价只是用户报告，不是研究独立核验的 gold truth；评价、分析结果和隐藏研究证据均不发送给 GUI Agent 或 Planner。
- 新会话事件 Schema 仍为 `1.3.0`；历史 `1.0.0 / 1.1.0 / 1.2.0 / 1.3.0` 不迁移。新增的是派生分析格式，不是重写历史运行条件。

本轮没有给真实的 18 条用户记录补评，也没有将它们导出。评价、导出及敏感字段排除测试使用隔离合成数据；真实记录仅进行无内容摘要保留复核。

## 电脑端本地分析

将手机导出的分析 CSV 保存到本地后，可用 Python 标准库工具处理：

```powershell
D:\Anaconda\python.exe -B tools/analyze_experiment_csv.py exported.csv --output local-analysis
```

工具生成 `summary.json` 与 `summary.csv`，拒绝覆盖已有同名输出；再次分析应使用新目录。省略 `--output` 时只向终端输出 JSON。它只读取规定的 45 列无内容 CSV，不读取手机任务附件、截图或密钥，也不自动上传。

可依次传入多个文件：

```powershell
D:\Anaconda\python.exe -B tools/analyze_experiment_csv.py earlier.csv later.csv --output local-analysis-updated
```

工具按 session ID 去重；同一任务在后续文件或行中再次出现时，后出现的快照覆盖前一个，避免重复导出被当作多次实验。覆盖顺序是命令输入顺序，不代表工具推断了任务发生时间。输出保留已评价／未评价、数值样本数及重复快照数量，不把不同计数单位混为实验总数。
