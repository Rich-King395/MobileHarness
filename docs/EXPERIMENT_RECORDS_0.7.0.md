# 本地实验记录增量：0.7.0

依据用户新要求：每个任务的实验记录至少包含用户下达的任务、使用步数、Planner 调用情况。本文件明确更新旧“任务原文只在 RAM”约定的适用范围。原 [数据边界快照](DATA_AND_LOGGING_BOUNDARIES.md)、提示词 manifest 和实验原文不改写；不能继续宣称本版本完全沿用旧版不保存任务文本的条件。

## 每条记录

- 任务原文：任务实际开始时，以同一随机 session UUID 保存最初下达的完整任务。列表显示两行，展开显示全文；后续恢复目标和人工操作不会覆盖原任务。
- GUI 使用：显示已用共享额度／总额度。失败、取消、等待和结束声明均按既有计账规则计算，人工操作不扣步、不重置额度。结束记录优先使用 session_ended 的最终值，活动记录取实际 started 调用的累计最大值；不按完成的点击数计算。
- Planner：显示已用次数／2 和 Harness 状态，展开逐次状态、耗时、已有 HTTP 状态、规划判断和决策。started／terminal 按角色和调用索引配对，不因两条事件把一次调用算成两次；失败／取消仍保留。调用回复通过不等于任务成功。

未调用与 Harness 关闭分别显示。没有记录的状态、决策或历史字段保持未知，不补造成功、零值或任务原文。超过两次的异常日志证据也不会为了外观截断；协调器规划上限不改变。

## 任务文本与原有元数据分开

| 数据 | 0.7.0 处理 |
| --- | --- |
| 已开始任务的原文 | Android Keystore 独立 AES/GCM 密钥保护，AAD 绑定 session UUID；保存到 noBackupFilesDir/local-task-records 的密文附件 |
| 计数、调用状态、规划分支、结束原因 | 继续写原最小事件 Schema 1.2.0，无任务或模型正文 |
| 当前任务草稿 | 仍只在 RAM，输入时不自动保存；不进入 Bundle／SavedStateHandle |
| 截图、模型回复、动作参数与输入内容历史 | 不新增持久化；截图仍仅按 GUI／Planner 必要观察暂留内存 |
| 人工期间画面与轨迹 | 不采集、不保存、不发送 |
| API Key | 沿用现有本机加密配置；不进入任务附件、普通日志或导出 |

附件的解密后载荷采用独立 [local-task-record v1](data-contracts/local-task-record.v1.schema.json)，只有 schema_version、session_id、task 三个字段；实际磁盘文件为 IV 与认证密文，不是明文 JSON。记录摘要不携带正文，只有用户打开记录页后才为可见卡片读取任务文本。展开状态和解密结果仅在页面 RAM 中，不写普通日志；诊断对象 toString 已脱敏。

记录页及任务输入处告知新增本机保存。现有导出入口明确叫“导出无内容日志”，仍只导出选中的已结束元数据，不包含任务附件，也不自动上传实验任务。旧任务原文未保存的记录显示“此记录未保存任务原文”；存在密文但无法认证／解密则显示“任务原文暂不可用”，可重读或删除。

## 生命周期

1. Audit.begin 在首个截图或模型工作之前提交任务附件，再写 session_started。附件写入或元数据起始写入失败会进入既有审计闭锁，不静默执行无记录任务；没有有效起始行的新附件会回滚。
2. 同一 session UUID 不可被另一任务复用。附件复制到另一 UUID、内容篡改或密钥丢失均不能被当作有效原文。
3. 进程重建仍只将未结束元数据补记 interrupted；本地任务附件仅供查看，不用于恢复执行、预算、历史、输入队列或人工证据。
4. 删除已结束记录时先移除附件及 AtomicFile 临时文件，再删事件日志。附件删除失败保留记录与重试入口；批量删除聚合实际结果，不能部分失败却显示全部成功。活动记录仍不导出／删除。
5. 启动清理没有有效日志的孤儿附件；不能确认有效性的不可读日志采取保留策略，避免擅自删除可恢复数据。

本增量改变的是实验记录的数据保留，GUI／Planner 请求、模型适配器 1.4.0、提示词 1.2.0、执行策略 1.1.0、人工信息隔离及 Harness 分支保持原实现。验证范围见 [0.7.0 验收](acceptance/TASK_RECORDS_0.7.0.md)。
