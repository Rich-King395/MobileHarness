# MobileHarness 0.1.3：启动与执行反馈第一轮改进

记录日期：2026-10-31；构建与本轮设备检查于 2026-10-30 晚完成。已构建并覆盖安装 0.1.3-dev（versionCode 4），保留本机模型配置与密钥。现有 43 项 JVM 回归通过，提示词 v1.1.0 与原交接材料保持不变。

## 已实现

- 正常启动不再只等待固定 600 ms：在新会话开始前，最多等待 8 秒确认主界面已离开、服务仍有效且目标 App 已在前台，才启动运行器。该短期检查仅读所选包名，不采集画面、文字或历史，不在人工阶段轮询。
- 无入口、服务条件失效、启动异常或前台未就绪时给出明确提示；尚未启动会话时不清除任务草稿，避免静默返回后丢失任务。重新回到主界面会取消尚未完成的启动。
- 状态文字区分获取画面、等待 GUI／Planner 回复、点击／长按／滑动／输入、等待画面刷新。只展示固定操作类型，不展示坐标、输入正文或模型思考。
- 界面将 GUI 计数明确标为请求次数，并说明失败、取消、等待、结束共用额度；人工不扣步，Planner 另计。
- 按已安装的 edge-to-edge 技能消费 Scaffold 边距并处理 IME；手机实测空任务框获得焦点、键盘出现后，输入框仍完整位于键盘上方。未在手机上穷举全部模型字段或旋转配置。
- 在任务页明确：操作发生于所选 App 的真实界面，运行中回到 MobileHarness 会接管或停止，应使用 MH 查看状态。

## 验证与仍待完成的工作

构建和 43 项协调器／桥接／请求适配单测通过；手机安装版本已核对，无障碍重新绑定。键盘布局检查通过。新增的正常启动握手与各失败分支还需逐项设备回归；单步诊断入口并不经过正常任务页，不能替代这些验收。

[计算器诊断](acceptance/CALCULATOR_DIAGNOSTIC_0.1.3.md)中，R-04 只确认任务终态未达成，没有建立 APK 故障归因；R-05 只证明一次落点映射与输入有效。按用户明确的 [验收范围](VERIFICATION_SCOPE_AND_ATTRIBUTION.md)，本版改进启动与交互合同，不以修复模型多步推理或提高任务成功率为目标，也不将这些交互改动称为计算失败的修复。旧记录保留原条件和结果。

当前改进没有新增模型请求轮次、查证权限、结束条件或隐式重试。点击标记、慢放、逐字输入、录像／回放不属于本版；如后续加入，需明确区分显示与执行策略。即使只是状态显示，也可能影响人的接管时机，User Study 前仍应固定 UI 版本并使开关组使用一致界面。
