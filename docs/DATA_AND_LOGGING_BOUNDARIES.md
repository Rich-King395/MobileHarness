# 最小日志与数据边界

确定日期：2026-10-30。适用于首期一次接管／归还、GUI Agent 与 Planner 分别直连远端的独立 APK。

本约定明确运行时数据与持久化日志的区别。当前为开发合同，尚未实现或通过真机验收。当前提示词版本为 [v1.1.0](MODEL_ADAPTER_AND_PROMPT_VERSIONS_v1.1.0.md)；v1.0.0 和原交接材料作为历史快照保留。

## 1. 数据保留总表

| 数据 | 运行时用途 | 本地持久化／导出 |
| --- | --- | --- |
| 当前截图、PNG、Bitmap、Base64 | 当前 GUI 判断或必要的 Planner 判断 | 仅内存；不写文件、缓存、数据库、普通日志或导出 |
| 接管前／归还／查证后边界截图 | Harness 恢复准备所必需的比较证据 | 临时内存槽，按用途释放；不形成截图历史 |
| 任务原文、提示词、模型回复、工具参数、动作文本历史 | 当前任务及阶段推理；Planner 可参考 Agent 自身已完成动作 | 仅会话内存；默认不保存或导出，不进入日志 |
| 人工期间画面、触摸、滑动、输入、无障碍节点变化 | 不采集，不用于推理 | 不保存、不发送、不导出 |
| API Key | 对配置的服务进行鉴权 | Keystore 加密保护后，本机私有且不备份的目录保存；不导出 |
| 服务地址、模型名及本人配置 | 分别配置 GUI／Planner；仅向对应服务调用 | 本机私有配置，不自动同步／共享；最小事件日志不复制这些自由文本 |
| 无内容事件日志 | 计步、耗时、控制权切换、错误定位和会话摘要 | 本机私有且不备份的目录；主动导出所选会话时仍只有白名单元数据 |

“不保存截图历史”也包括：不在旧 `messages` 中积累或重复发送 `image_url`／Base64，不保存图像哈希、缩略图、录像、OCR 副本或可回放的屏幕记录。不使用磁盘 HTTP 缓存、请求／响应正文日志、自动崩溃附件或分析 SDK 收集这些数据。应用私有 `cacheDir` 仍是磁盘，不能用它实现“仅内存”。

## 2. 截图的最小生命周期

### 2.1 GUI：每次请求恰好一张当前画面

- 按决策需要取图，不连续录屏、不按定时器建立截图历史。
- 文本会话和临时图像存储分开。请求组装时只附本次有效的当前 PNG；旧图像及其配套“附图／最新图像”包装文字不进入后续请求。
- 原任务、阶段内文本、Agent 自身工具调用及执行反馈继续保留；保持原生 `assistant.tool_calls` 与 `role=tool` 的 `tool_call_id` 配对。移除历史图片不等于切换阶段、摘要文本或删除动作历史。
- 新帧取代旧帧后，立即释放旧帧引用；只有仍承担下述 Planner 边界用途的帧可以暂留。过期坐标不能据此重新使用。

### 2.2 Planner：最多三种有明确用途的边界帧

| 临时槽 | 何时取得 | 用途与释放 |
| --- | --- | --- |
| 接管前边界帧 | 接管请求前已经取得的最后一张有效画面 | 有必要时供恢复判断；缺失或已失效则为 null，不补拍人工过程 |
| 归还帧 | 用户主动归还、采集权限及控制权检查通过后新取得 | P1 的当前观察；进入只读查证后，仅在 P2 仍需比较时保留 |
| 查证后最新帧 | 一轮 VERIFY／CONFIRM 内观察当前画面或等待刷新后取得 | 替换该阶段较旧的刷新帧；供 P2 判断或当前 GUI 使用 |

- 逻辑上最多保留这三种**不同证据帧**，同一帧按引用共享和去重；它们不是按步归档的截图历史。编码、HTTP 序列化和系统截图回调可能有额外短暂缓冲区，不能把三个逻辑槽说成进程中绝不出现第四份像素副本。
- P1 最多使用接管前帧和归还帧；P2 只附最新帧及仍确有比较需要的边界帧。不能为了凑满槽位拍图或附图。
- P1 已交付 EXECUTE／FALLBACK 时立即释放 Planner 专用帧；需要一轮只读查证时，仅保留 P2 尚需的边界帧。P2 交付或直接结束后立即释放；成功确认直接结束也同样释放。
- Harness 关闭时没有 Planner 帧保留用途。人工模式释放旧 GUI 画面，归还只取新画面，原任务文本历史继续。
- 接管前帧可能早于 Agent 最后一个动作的业务结果，不能把前后画面所有差异都归因于用户。

### 2.3 从“暂停中”开始就停止采集

接管请求进入本地协调器时立即关闭观察入口、取消尚未开始的采集和等待刷新，并使旧代次回调失效；不等到界面显示“人工控制”才停止。迟到的截图回调直接丢弃并释放，不能被送给模型、写日志或成为边界帧。保留的接管前帧必须在接管请求前已经获得。

人工期间不订阅、缓存或导出触摸／输入轨迹，不构建 UI 节点快照或窗口变化序列。系统可能仍回调必要的无障碍服务事件，应用应在入口处忽略其内容；不能把“系统没有回调任何事件”作为承诺。用户点击本应用的接管、归还和停止按钮，只记录控制权事件及相对时间，不记录两者之间的手机操作。

已发送的旧网络请求可能仍在服务端运行；取消请求和屏蔽回复不能撤回对方已收到的截图。旧回复不执行、不进入有效历史，缓冲区在调用结束／取消回调后释放，不为等待 HTTP 取消确认而拖延人工控制。

### 2.4 结束、异常和进程退出

- 正常结束、用户停止、额度耗尽：释放全部截图、请求体及会话内容引用，只保留最小元数据摘要。
- 模型／手机错误：清除截图及不再使用的网络缓冲区。若仍在同一进程中允许显式恢复，保留必要文本状态、预算和阶段；恢复须按原阶段规则取得新图，不能补拍或重建人工期间画面，也不能增加 Planner 调用。丢失的边界帧按缺失处理。
- 无持续任务的后台空闲状态不留截图。仅切到目标 App 不算结束，否则无法在目标 App 上运行。
- 不将会话正文、截图或可执行队列放入 `SavedStateHandle`、Bundle、任务恢复文件或持久化数据库。进程被杀后不自动恢复操作，旧会话标为中断；用户可以从当前手机状态发起新任务，不能假装恢复旧预算和旧历史。
- “释放”指主动去除引用、关闭图像资源并尽力清除可控缓冲区，不承诺 Android／运行时所有内存副本能被立即物理擦除。

## 3. 最小持久化日志：只用白名单字段

公共字段仅包含：日志 Schema 版本、本地随机 `session_id`、递增 `seq`、相对会话开始的 `elapsed_ms`、事件类型及对应结构化数据。不默认记录绝对时间、设备序列号、账号、研究参与者身份、目标 App 包名或服务地址。

| 事件 | 允许的内容 |
| --- | --- |
| 会话开始 | Harness 开关、GUI 额度、提示词包／适配器版本、包 manifest 哈希、两角色本地随机配置 ID |
| 控制权事件 | 请求接管、屏障成立进入人工、请求归还、归还提交、请求停止、暂停未确认 |
| 模型调用 | 角色、阶段、实际调用序号、开始／结果状态、耗时、已用 GUI／Planner 额度、可选 HTTP 状态码 |
| Agent 动作 | 阶段、GUI 步号、动作类型、执行完成／拒绝／取消／未知／设备错误；finish 另记阶段声明 completed／unable |
| Planner 决策 | 第几次调用、completion_status、decision；不记录 objective 或条件正文 |
| 错误 | MODEL／DEVICE／COORDINATOR 分类、预定义错误码，不记录原始报错字符串 |
| 会话结束／用户评价 | 结束原因、结束声明来源、已用额度；用户是否认为完成独立记录，未评价为 unknown |

字段及合成例子见 [严格事件 Schema](data-contracts/minimal-event.schema.json) 和 [合法／非法示例](data-contracts/minimal-event.examples.json)。每个对象禁止额外字段；序号、调用关联和跨事件计数还需协调器验证，Schema 本身不能证明日志事实正确。

具体规则：

- 实际 HTTP 尝试前先计账并记录 started；同一角色和调用序号的结束事件补充结果，结束事件不再扣一步。来不及记录结束的 started 表示结果未知，不能当成功或退款。尚未发出的本地预检失败只记错误，不伪造调用。
- Agent 动作只记录类别与执行状态；不保存输入文本、点击坐标、控件文字、目标对象、启动包名或任何工具参数。模型原始回复、finish.message、思考内容、任务原文及其摘要一律不进入最小日志。
- 模型／网络／格式错误归 MODEL；采集、授权、输入等手机执行问题归 DEVICE；预算或协调状态问题归 COORDINATOR。`finish(unable)` 记录阶段未完成，不自动归为模型错误。
- 模型完成声明、自动流程结束、用户判断和研究者核验是不同概念。P2 的 COMPLETE＋FINISH 可直接结束；日志不能据此把成功标签设为 true。首期不内置研究者隐藏评分字段，也不向模型传递用户评价。
- 不默认记录 token 计费、厂商 trace ID、端点、自由文本调试备注或截图计数序列；如后续研究确需新增，单独修订数据契约。

## 4. 本机配置、密钥和网络边界

- GUI／Planner 使用各自配置与 Key。使用 Android Keystore 中不可导出的加密密钥加密 API Key，密文存入应用私有 `noBackupFilesDir`；不把 API Key 明文写入 Preferences／DataStore、源码或构建产物。
- API Key 仅供本人本机使用，不建立共享密钥服务、不经过项目自建代理。发起请求时短暂解密到内存，仅向对应配置的 HTTPS 服务发送鉴权头，不把 Key 拼入 URL、提示词、图片、日志或导出。两角色可以由用户配置相同 Key，但不得自动跨服务复用。
- 服务地址、模型配置和日志也存入不备份的私有目录；Key 更换／删除后清理旧密文及相关内存引用。Key 不进剪贴板自动复制、崩溃附件或通知。配置 ID 为随机引用，不是 Key 或配置内容的哈希。
- 应用敏感配置页遮蔽 Key，禁止本应用页面截图和最近任务缩略图，并在该页暂停模型采集；这些保护不能控制其他 App 的画面，也不能保证目标 App 自己从不展示其敏感信息。
- 为 minSdk 30／targetSdk 36 明确设置 Android 11 及以下的备份规则和 Android 12+ 的云备份／设备迁移排除。不能仅凭 `allowBackup=false` 宣称所有厂商换机工具均受控。

启动前的知情文案采用：

> 任务文字和当前屏幕截图将发送到你配置的 GUI Agent 服务；开启 Harness 时，恢复规划所需的任务、Agent 自身动作和少量边界截图还会发送到 Planner 服务。人工接管期间不采集画面和操作轨迹。截图仅在手机内存中临时使用，不保存截图历史。远端服务如何留存和使用输入输出，取决于该服务的政策。

两角色服务地址应在配置和启动检查中可见。两者指向不同服务时，也必须说明两者各自接收数据。客户端的不落盘约定不能保证服务端零留存；已发送的数据不能通过本地删除撤回。阿里云百炼个人版的套餐适用范围、输入输出使用政策和后续研究安排仍按实际服务条款处理，不把本地政策表述成厂商承诺。

## 5. 删除和主动导出

- 最小元数据日志首期保留在本机，直到用户删除；支持删除单次会话和全部记录。不自动上传、同步或生成研究数据包。
- 导出由用户主动选择会话、确认目标后执行，仅序列化白名单日志；不复制配置文件、Key、会话正文或任何图像。临时分享文件按分享完成／有效期清理，用户另存或交给他人后的副本由其管理。
- 后续 User Study 的参与者编号、服务／模型版本披露、日志保留期限、结果评价与研究导出格式另行确定；不会因开启 Harness 自动扩张采集范围。

## 6. 最小 APK 阶段需要实测

1. 多步 GUI 请求只有最新一张图；旧图及包装文字已移除，工具消息关联保持有效。
2. Planner 只附必要边界帧、编号去重；缺图明确为 null；准备结束无专用帧引用。
3. 接管请求至人工期间无有效采集；迟到回调丢弃，归还后确实取新图。
4. 检查私有文件、cacheDir、数据库、网络缓存、Logcat、崩溃路径和导出，无截图／正文／Key 泄漏。
5. Key 密文与日志排除标准云备份／迁移；敏感配置页与最近任务预览正确遮蔽。
6. 正常结束、错误、停止和进程重建后，不残留可自动执行的旧任务或图像引用；日志保持模型／设备／任务结果区分。

当前只能验证文件与契约结构。尚无 APK，因此没有把上述运行时行为标为“已通过”。

## 7. 平台依据

- [Android Keystore](https://developer.android.com/privacy-and-security/keystore)：保护加密密钥材料，API Key 仍需在调用时短暂解密。
- [应用私有文件与缓存](https://developer.android.com/training/data-storage/app-specific#internal-access-create-cache)：cacheDir 是文件存储，不是内存。
- [Auto Backup](https://developer.android.com/identity/data/autobackup) 与 [Android 12 备份／迁移变更](https://developer.android.com/about/versions/12/behavior-changes-12#backup-restore)：私有存储不等于自动排除备份。
- [setRecentsScreenshotEnabled](https://developer.android.com/reference/android/app/Activity#setRecentsScreenshotEnabled(boolean)) 与 [FLAG_SECURE](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SECURE)：用于本应用窗口／任务预览保护，不代替截图生命周期控制。
