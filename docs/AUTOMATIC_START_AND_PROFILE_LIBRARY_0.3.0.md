# 自动启动、多配置和白色界面：0.3.0

日期：2026-10-31。当前开发版本：0.3.0-dev（versionCode 6）。依据用户选择：自动选择 App，预先设置可复用授权范围。

## 任务启动

手动指定初始 App 是旧 APK 的启动实现要求，不是 Harness 方法本身的要求。新入口将“启动位置”和“授权 App”分开：用户先保存可操作 App 范围，此后直接输入任务，从系统实际默认桌面开始，由 GUI Agent 选择并打开授权 App。

默认桌面必须明确解析并固定组件；没有默认桌面或前台未就绪时保留草稿，不发模型请求。任务启动冻结本次授权集合和名称映射，新安装 App 不自动加入。修改范围需用户主动保存，关闭选择面板不提交。

桌面是导航上下文，不是全手机授权。桌面上不允许任意坐标点击、长按、滑动或输入；Agent 使用 launch_app 打开授权 App。Home／Back、wait／finish 仍受阶段和控制权限制。VERIFY／CONFIRM 的只读规则不变。

每次观察在截图前、隐藏控件等待后、交付图片前检查前台范围；旧帧还绑定所属 App，避免跨 App 派发。人工期间不轮询包名或窗口。归还时如果当前 App 不在范围内，在截图前拒绝，继续保留人工控制，不消费归还机会、不额外调用 Planner。用户可以回到授权 App 后再次主动归还。

Pixel 4／Android 13 仍使用整屏截图。前台范围检查只能降低误发风险，不能保证截图瞬间没有通知、键盘或其他覆盖窗口。它不构成严格的逐 App 图像隔离，也不会通过静默裁图或涂抹改变原坐标约定。

## 配置库

配置库支持保存多份命名配置，GUI Agent 和 Planner 各自明确选择，也可以共用同一份。新建、改名、编辑、删除和角色选择在运行／启动期间禁用。新增配置不自动绑定角色；删除被选配置会清空对应选择，不悄悄改用其他模型。

旧 GUI／Planner 两份配置在手机内迁入 Keystore 加密的 AtomicFile 配置库。相同服务地址但不同 Key 的配置不合并；原修订 ID 和原角色选择保留。新库完成写入、认证读取和内容比较后才清理旧加密文件。异常时停止迁移，不以空库覆盖本人配置。

配置槽 ID 稳定，每次保存产生新的修订 ID。读取 Key 时同时匹配修订、规范服务端点和模型名称；旧任务快照不能读取修改后的凭据。服务地址变化时必须重新输入对应 Key。元数据不返回 Key，Key 不进入普通日志、导出、源码或电脑。

“多份配置”与“厂商接口已适配”是两件事。当前执行适配器仍为 Qwen phone tools，其请求含 Qwen 专用字段；保存 GPT／Claude 的名称和地址不会自动提供对应原生 API 支持。没有为这些模型静默删除参数、改写提示词或添加重试。后续新增厂商适配器应单独版本化并验收。

## 界面与数据

默认使用白色背景、黑色正文、蓝色文字和浅蓝色按钮；系统栏使用深色图标。重复引导文字删去，必要授权、远端发送同意、状态和错误提示保留。

授权 App 范围是用户主动保存的本机设置，单独加密保存在不备份的私有目录。只存包名集合，不保存任务、人工轨迹或截图；这不是向最小事件日志增加 App 身份字段。任务与草稿仍只在 RAM。

自动任务使用显式的增量提示词包 1.2.0，继承冻结 1.1.0 的恢复方法和执行格式。旧 1.0.0／1.1.0、原始英文提示快照和旧实验记录保留。新启动上下文不能宣称与旧实验条件完全一致。日志 Schema 1.0.0 已允许语义版本号，新版本／manifest 哈希按实际所用包记录；不增加内容字段。

已构建、签名验证并覆盖安装到 Pixel 4。60 项 JVM、6 组隔离配置库、真实桌面／授权 App 启动、截图前授权拒绝、浅色悬浮条排除与原四组 PhonePort 回归通过；新增配置的空 Key 与固定保存按钮均位于键盘上方。本人两份配置已迁移，未替用户选择授权 App 或更改角色绑定。本轮远程模型调用为 0。范围与证据见 [验收记录](acceptance/AUTOMATIC_START_AND_LIBRARY_0.3.0.md)。
