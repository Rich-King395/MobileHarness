# 当前模型与提示词约定 1.1.0

日期：2026-10-30。状态：数据边界修订，未作真实 API 或手机验收。

当前可执行提示词包为 `prompts/v1.1.0`。本页与 [最小日志和数据边界](DATA_AND_LOGGING_BOUNDARIES.md) 覆盖 [1.0.0 规格](MODEL_ADAPTER_AND_PROMPT_VERSIONS.md) 中有关图像历史、持久化记录和版本路径的旧约定。其余动作、坐标、采样参数、Planner 分支、预算及阶段语义沿用；旧规格和 `prompts/v1.0.0` 原样保留，不能将本次修订称为与旧实验完全一致。

## 1. 本次改变

| 内容 | 当前约定 |
| --- | --- |
| GUI 图片 | 每次请求恰好一张有效当前全屏 PNG；不保留或重复发送历史截图 |
| GUI 文本 | 保留所选阶段的文本历史及原生工具消息关联；不自动摘要／截断文本 |
| Planner 图片 | 仅必要的接管前／归还／查证后边界帧，按编号去重，逻辑槽最多三帧 |
| 本地截图存储 | 仅内存、按用途释放；文件、磁盘缓存、日志、导出及备份均不允许 |
| 人工期间 | 从接管请求起停止采集；迟到回调丢弃；归还后新观察 |
| 日志 | 只持久化白名单元数据，不保存任务、提示词、回复或工具参数正文 |
| Key | 本机 Keystore 加密保护的私有配置，仅供本人使用；不备份、不导出 |

这是一项显式图片历史策略修订，而非接口超限时的临时删图。`automatic_text_history_truncation=false` 仍成立；旧版 `automatic_history_truncation=false` 不再用于禁止清理历史图片。文本或必要图片仍超限时显式暂停，不通过隐藏摘要、压缩、增加请求或重试规避。

## 2. 请求与内存组织

GUI 文本会话与临时帧存储分开。原任务、阶段目标、同阶段文本、`assistant.tool_calls`、`role=tool` 与 `tool_call_id` 的关联保持完整。旧 `image_url`、Base64、旧观察尺寸／编号及“所附 PNG 是最新画面”等图像包装不成为持久会话消息；每次在历史文本之后新附 `gui-observation.template.txt` 和唯一当前 PNG。旧文本动作与反馈仅是历史证据，不能被包装成当前画面。

Planner 的文本 `own_action_history` 仍限 Agent 自身已完成动作，是运行时推理输入而非持久化动作日志。P1 只发送当前归还帧和确有必要、已经存在的接管前帧；P2 只发送当前最新帧及仍需比较的边界帧，不发送查证过程中每次等待刷新的图像序列。两次请求分别以各自系统提示和当前输入组装，不累积前一次的图片 messages。

`images` 编号与实际图像一一对应、去重，`current_frame_id` 对应唯一最新图。接管前帧不可用时，`pre_handoff_frame_id=null` 并移除对应描述及图像，不补拍、不伪造。边界帧在无后续 Planner 用途时立即释放；完整生命周期见数据边界文档。输入示例是合成结构示例，不是截图归档要求，也不代表所有槽位必须填满。

Harness 关闭及 FALLBACK 均继续原任务的文本历史并附新图，不调用图片历史恢复。清理旧图片对有无 Harness 一致，不能将其算成 Harness 专属历史切换。VERIFY／CONFIRM／RECOVERY 依然各建新阶段文本对话，不把 Planner 所见旧文本或边界图注入新 GUI 对话。

## 3. 保持的恢复规则

- 第一次 COMPLETE 必须进入仅观察当前画面／等待刷新的只读确认；确认完成可结束。
- 一次归还最多两次 Planner 请求和一轮只读阶段。P2 的 COMPLETE＋FINISH 由协调器直接结束，不追加 GUI done 或新一轮查证。
- 执行交付后不持续重规划；回退从当前手机状态继续，不撤销用户操作。
- GUI 默认总额度 30，共享查证、执行、失败和结束声明；人工操作不扣步数、不重置额度；Planner 另计，没有隐藏重试。
- 模型结束声明不等于任务成功。最小日志分别保留声明来源、错误分类及独立用户评价。

## 4. 版本与验收

- `bundle_version=1.1.0`，`adapter_version=1.1.0`；模型、工具参数 Schema、Planner 输出 Schema、全屏 PNG 格式及 0…999／1000 坐标映射不变。
- `prompts/v1.1.0/manifest.json` 记录本包文件、当前补充规格、数据边界及日志契约哈希，并引用完整保留的 1.0.0 基线 manifest。这里的哈希是协议文件哈希，不是用户截图哈希。
- 会话开始只记录版本、manifest 哈希和本地随机配置 ID，不把配置内容或 Key 混入日志。
- 离线检查结果见 `prompts/v1.1.0/VALIDATION.md`。网络端点、内存释放、文件／日志泄漏、备份排除和真机暂停竞态必须在 APK 阶段验收，不能由静态 Schema 检查代替。
