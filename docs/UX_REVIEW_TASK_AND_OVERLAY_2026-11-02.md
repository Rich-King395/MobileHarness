# 任务页与悬浮控制：精简改版审查

日期：2026-11-02。基于当前 0.3.5-diag 源码及既有合成预览。本轮交付设计材料，未修改 Android 源码、安装 APK、读取手机或调用 GUI／Planner。

## 审查结果与改版范围

现有白底、多配置库、授权范围、接收服务摘要、主动同意、截图隐藏和输入避让均已实现。本稿在现有能力上整理视觉层级。

| 现有问题／依据 | 本稿改动 |
| --- | --- |
| 浅蓝外容器内还有输入框、授权大按钮及多个边框，层级偏多；`MainActivity.kt:628–655` | 去掉大块外容器；保留一个任务输入框，授权范围／Harness／预算采用紧凑控件，窄屏可换行。 |
| 输入只有占位文字；灰色开始按钮未覆盖所有阻断原因；`:630–633, 668–674` | 持续显示“任务”标签；按钮上方一次只呈现首个阻断原因。开始条件保持原有条件。 |
| 接收者摘要已齐全，但占据较多纵向空间；`:657–666, 695–715` | 两条紧凑接收服务行，仍显示角色、配置名及域名；完整地址、模型及数据边界按需展开；同意不预选。 |
| 状态球只展开，接管在面板里；停止是独立按钮；`OverlayControlPanel.kt:104–110, 180–224` | 保留该动作映射，区分状态、计数、主动作；暂停／待确认／人工使用不同文字；停止保留独立 48dp 触点及明确标签。 |
| 通知正文显示原始状态枚举；`HarnessAccessibilityService.kt:788` | 提议改成与悬浮面板一致的中文状态，命令、token 校验和认证规则照旧。 |

视觉沿用白底、黑色正文、浅蓝按钮，统一 4／8dp 间距；按钮触点至少 48×48dp。任务页只强调“开始任务”，运行面板只强调当前允许的主要动作。预览位置仅是合成时钟示意，不是按内容重定位算法。

## 控制权与按钮映射

| 真实运行状态 | 面板动作（独立停止按钮另列） |
| --- | --- |
| 自动，尚未归还 | 接管；停止任务 |
| 暂停中 | 仅停止任务；等待真实输入终态 |
| 人工 | 归还控制；停止任务 |
| 准备中／查证 | 仅停止任务 |
| 待确认 | 重新检查暂停、打开应用；停止任务 |
| 需处理 | 重试、打开应用；停止任务 |
| 自动，已成功归还一次 | 仅停止任务 |
| 停止中 | 不开放新命令，停止按钮禁用 |
| 空闲／已结束 | 打开应用 |

“暂停中”只有在执行器确认没有在途输入时才能变为“人工”；5 秒超时进入待确认。等待网络取消完成不是授予人工控制的条件。第二次 Planner 判定完成直接结束，结束文案保留“结果待独立确认”。

截图时整个悬浮窗口隐藏，等待显示帧后取图，随后恢复收起；本稿不增加保持展开、自动暂停或延后截图的规则。悬浮窗仍占用少量屏幕区域，通过贴边、收起及原有拖动减少遮挡；执行冲突时移动自家窗口，保持模型原落点。

运行中不新增“回主页只看进度”入口：当前主页前台恢复会触发首次接管，已用过接管则停止。通知正文进入主页与通知中的接管／归还动作继续区分。

## 交互检查清单

以下项目是后续 Android 实施与真机验收清单，尚未因本预览而通过。已完成的旧版检查继续按各自版本与范围保留。

- [ ] 空任务、空授权范围、模型缺失、服务／控制入口未就绪、无效额度、未同意分别显示准确的开始阻断原因。
- [ ] 服务地址、模型或 Harness 改变后清除旧同意；发送详情与实际接收者一致；OFF 不显示为本次调用 Planner。
- [ ] 默认字号、系统较大字号、360／393dp、真实键盘及横屏下，任务、同意和开始按钮均可到达且不被系统栏遮住。
- [ ] 状态球点击只展开／收起；拖动与点击不误触；48dp 触点不重叠，不扩大透明窗口吞掉目标 App 操作。
- [ ] 接管后立即停止新增派发／采集；暂停中不出现归还；真实输入终态前保持暂停／待确认。
- [ ] 人工期间不读取画面、节点或操作轨迹，不增加 GUI 步数；人工操作在归还后保留。
- [ ] 归还失败回人工且仍可再试；新画面成功提交后才消耗一次归还，计数不重置；之后自动状态仅提供停止。
- [ ] 截图隐藏整个自家控件，恢复收起；展开后紧接采图时仍能找到接管入口，不加入额外暂停／锁定逻辑。
- [ ] 原有窗口避让继续只移动自家控制条，模型动作参数与落点不变。
- [ ] 真实通知面板的接管、归还、停止及锁屏认证可用；旧任务／旧 token 被拒绝，返回主页的行为与现有规则一致。
- [ ] ON／OFF 两条真实接管路径信息条件正确；受改动影响的历史隔离、共享预算、两次规划／一轮查证、P2 直接结束通过既有确定性回归。
- [ ] 模型声明结束、用户停止、额度耗尽与设备／协议问题可区分；不把声明结束标为任务成功。

浏览器预览按钮具有文字标签和焦点样式；原生悬浮根节点当前设置了 `IMPORTANT_FOR_ACCESSIBILITY_NO_HIDE_DESCENDANTS`，不能据此宣称 Android 读屏可用。该边界后续单独审查，本轮不改变节点暴露策略。

## 设计依据与验证边界

使用项目安装的 ui-ux-pro-max 2.15.0：`touch target spacing --domain ux`、`loading feedback --domain ux`、`state hoisting semantics --stack jetpack-compose`，结合其原生界面检查表。采用 Android 48dp 触点、异步状态反馈、单一主要动作及清晰表单标签；未采用通用 `rememberSaveable` 建议保存任务、截图、密钥或执行状态，未引入新框架／依赖。

离线 Chrome 最终 39 项预览检查通过，覆盖典型交接状态、共享预算示意、OFF 路径、360／375px、合成键盘和局部文字放大。它验证的是设计演示，不是 Coordinator 或新的 APK 验收。真实系统字号、IME、手势、通知认证和截图时序仍按上述清单验收。

本轮不改变 Harness、提示词、模型协议、日志及数据边界；ARGB 暂缓。任务页和运行页并排展示两个时刻，不表示实际任务期间允许修改配置。

后续已按用户授权实施为 0.4.0-dev 并覆盖安装；实现与有限设备验收、未通过记录及横屏边界见 [实施记录](acceptance/UI_AND_OVERLAY_0.4.0.md)。本设计稿的离线检查不追溯改称真机验收。
