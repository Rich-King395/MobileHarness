# 最小交互与运行状态

版本：交互设计 1.0。日期：2026-10-30。状态：设计稿，尚未在 Android APK 上实现。

本设计沿用已确认的技术基线；当前提示词为 prompts/v1.1.0，旧版原样保留。图片与日志遵守 [最小数据边界](DATA_AND_LOGGING_BOUNDARIES.md)：GUI 只附当前图、Planner 仅使用必要边界图、人工期间不采集、截图不落盘。首期每任务支持一轮接管与归还；停止自动操作始终可用。

## 1. 最小界面

### 任务页

    MobileHarness                            模型设置
    App           [选择手机上的 App]
    任务          [输入自然语言任务]
    恢复辅助      [Harness 开关]
    总步数        [30，可修改]
    入口检查      无障碍 / 悬浮条 / 通知备用入口
    截图与任务指令会发送到配置的模型服务
                    [开始任务]

App 选择来自设备上可启动且用户允许使用的 App，不限定任务集或起始画面。模型设置分别配置 GUI Agent 和 Planner；Key 默认遮蔽。通知权限或渠道不可用时明确标注，不能显示为备用入口已就绪。

Harness 和总预算在任务开始前确定；运行中查看配置不会静默改变当前会话的研究条件。

### 模型设置页

- GUI Agent、Planner 分别设置服务地址、模型名、Key。
- Key 采用安全保存和遮蔽显示；本页不进入模型截图输入。
- 返回任务页不启动自动执行。服务连通性测试若将来加入，独立显示其请求与费用，不隐式消耗任务预算。

### 结果页

显示结束原因、GUI 已用步数、Planner 请求次数和错误分类。

分别保留“模型/Planner 判断结束”“用户认为完成”“研究者核验成功”。用户可选认为完成或未完成，也可稍后判断；不能把自动流程结束直接标为任务成功。

结束或停止后保留当前目标 App，不自动跳转或遮住用户工作。悬浮条和通知显示结束状态，用户点击“查看结果”才打开结果页。

## 2. 悬浮控制条

默认使用小范围、可移动且可收起的无障碍浮层。只让控制条自己的窗口接收按钮触摸；不覆盖整个屏幕拦截操作，也不让按钮点击透传到底层 App。

展开态：

    自动执行 · 已用 7/30         [收起]
           [接管]  [停止任务]

    暂停中 · 正在结束当前操作
           [接管处理中] [停止任务]

    人工控制 · 你可以自由操作
           [归还控制] [结束任务]

    恢复准备 · 正在获取新画面 / 规划剩余工作
           [准备中]  [停止任务]

首次归还后，再次自动执行时：

    自动执行 · 已用 9/30
           [停止并手动继续]

该入口同样经过安全停止屏障，但终止本任务的自动流程，不再提供第二次归还。它不能因为首期只支持一次接管就被禁用。

收起态仍显示状态与主要操作。人工控制时保留明显的“归还”入口。收起只改变控制条大小，不改变控制权，不计 GUI 步数。

## 3. 通知栏备用入口

通知标题、状态、步数与悬浮条来自同一状态源，按钮发送同一种本地事件：

| 当前状态 | 通知按钮 |
| --- | --- |
| 自动执行、尚未接管 | 接管 / 停止任务 |
| 暂停中 | 停止任务 |
| 停止处理中 | 仅显示状态，不重复发送停止操作 |
| 人工控制 | 归还控制 / 结束任务 |
| 恢复准备、查证或确认 | 停止任务 |
| 首次归还后自动执行 | 停止并手动继续 |
| 暂停未确认 | 打开应用 / 重新检查暂停 / 停止任务（待确认） |
| 已结束或已停止 | 查看结果 |

通知正文不展示任务原文、截图、Key 或其他敏感内容。Android 13 的通知权限、渠道设置及锁屏策略会影响可见性；系统 Task Manager 不能替代本应用的通知按钮。

通知动作使用明确组件和不可变 PendingIntent，并校验当前 task、控制权代次与允许状态。旧通知的“归还”不能启动一次额外恢复。重复点按是幂等事件。

锁屏时停止和接管请求可以用于关闭自动派发；恢复自动执行必须先解锁并通过授权与执行器检查。通知正文或按钮不能绕过该检查。

打开本应用控制界面时，坐标动作不得落到该控制界面；通知抽屉及系统控制面板展开时的输入暂缓与观察失效策略，需要在 Pixel 4 上单独验收。

“自动执行”内部阶段可显示“分析画面”“执行操作”“恢复执行”“按原任务继续”。状态显示使用中文目的描述，程序阶段标识保留在会话记录中。

恢复准备先获取新观察，再按 Harness 开关选择路径；它不是已经恢复了输入派发。任何恢复路径都不重置 GUI 额度。新任务才建立新的预算。

模型、截图、授权和设备问题进入“已暂停·需处理”的错误展示，不自动归类为任务失败。错误时同样关闭派发；若仍有未确认的在途输入，优先显示“暂停未确认”，不能给出已安全暂停的承诺。

错误恢复不重置步数、阶段或 Planner 次数；Planner 自身请求失败按既有回退合同处理，不借“重试”隐式增加第三次规划。归还过程尚未获得有效新画面的失败，优先回到人工控制保留手动操作。

同进程中的暂停可以保留必要文本状态；截图在错误时释放，恢复按原阶段取得新图。会话正文与执行队列不持久化，因此进程被杀后旧会话标为中断，不自动恢复操作；用户可从当前手机状态发起新任务。正常结束／停止后清除会话内容，只留下最小元数据。

## 5. 暂停中何时变成人工控制

接管事件进入本地串行协调器时，立即执行：

1. 关闭所有自动动作派发入口，更新控制权代次。
2. 使旧模型请求、响应及旧坐标失效，撤销尚未提交的本地动作队列和定时派发。
3. 暂停观察采集；迟到截图不作为人工期间证据留存或发送模型。

随后等待已提交输入的终态。只有同时满足以下条件，才能发出“人工控制已就绪”并更新两种入口：

| 屏障条件 | 确认依据 |
| --- | --- |
| 不再有新输入派发 | 本地派发门已关闭，所有队列/定时回调受新代次约束 |
| 旧模型回复无法再触发操作 | 请求归属校验已生效；迟到回复直接丢弃 |
| 已提交输入已结算 | 手势收到完成/取消，其他执行器操作也已确认无继续注入输入的在途操作 |
| 人工期间不采集观察 | 观察调度已停，旧捕获结果由代次检查丢弃 |

特别区分：

- HTTP 取消确认不属于等待条件。远端请求可以继续收尾，只要其旧结果已经无法派发输入。
- dispatchGesture 返回 true 不是手势已完成；要等待 GestureResultCallback 的完成或取消。
- 取消协程、清空应用队列也不能代替已派发动作的终态。
- 不派发另一个手势作为“无副作用取消”，不回滚已经发生的修改。
- 不要求目标 App 的后台业务请求结束或画面完全静止。App 自身刷新和保存可能继续；屏障保证的是本 Agent 已无继续派发输入的在途操作。

若本来就没有在途输入，本地屏障成立后可立即进入人工控制，不人为等待固定时长。若有在途输入，即使旧网络请求已经取消，也继续保持暂停中。

真实手机不通过全屏浮层锁住用户触摸。暂停中显示“请先等待交接确认”，但不能声称系统已经阻止用户提前触摸其他 App。

“5秒”仅是首版异常提示阈值，不是自动交接倒计时。超时显示“暂停未确认”，保留关闭的派发门，并提供重新检查和打开应用入口；不能仅因时间到就置为人工控制。若终态稍后到达，根据当前有效意图进入人工控制或已停止。

暂停未确认时仍可请求停止：只将有效意图改为停止，界面继续显示尚未确认；终态到达后进入已停止，不再开放归还控制。

## 6. 归还与停止

归还流程：

    归还请求 → 检查解锁/授权/执行器 → 获取新画面 → 恢复准备
       ├─ Harness关闭：相同通知 + 原任务历史，直接继续
       └─ Harness开启：第一次Planner → 执行 / 一轮当前页检查 / 回退
                                        └→ 第二次Planner可直接结束

归还检查或新截图失败时，保留人工控制并明确显示原因，用户可以继续手工、修复后再试或结束。未发出模型请求的本地失败不伪造模型计步，也不消耗新的接管次数。

获得有效新观察、准备正式继续后，本轮接管归还才标记为已使用。若已发出恢复规划请求，则按该轮既有规划次数继续，不允许通过重复点击归还重置两次上限。

停止没有二次确认弹窗来拖延关闭派发。自动状态先进入停止处理中，使用同一屏障；确认无在途输入后才显示已停止。人工状态下结束任务可直接完成，因为输入屏障已经成立。

恢复准备、查证、确认时也始终提供停止。用户从通知或悬浮条触发的接管、归还、停止属于控制事件，不消耗 GUI 模型步骤；已经发出的模型请求不因取消或丢弃而退步数。

## 7. 浮层、截图与入口可用性

- Pixel 4/API 33 使用全屏截图，不能假定系统会自动排除无障碍控制条。
- 如截图时暂时隐藏控制条，需在取得画面后恢复，并在真正派发前验证目标不被恢复后的控制条遮挡；截图清楚不等于输入可达。
- 控制条隐藏期间若通知备用入口不可用，不应开启新的自动输入窗口。至少保留一个已验证的可用制止入口。
- 目标被控制条遮挡时不执行会落到控制条的坐标动作。如何移动控制条、重新取图及保持代次一致，放入最小 APK 验收。
- 输入法弹起时，控制条保持主要按钮可达并避让键盘，不抢走输入焦点；其按钮触摸不能透传到底层 App。
- API 34 的窗口截图是另一种图像/坐标范围，不能静默替换冻结的全屏协议。
- 通知权限、渠道、无障碍连接和浮层都要按实际状态显示。主入口与备用入口都不可用时，关闭派发并暂停运行。

## 8. 首期验收场景

完整 Given／When／Then、计数和模型可见信息断言见 [验收场景入口](acceptance/README.md)。以下列表保留为交互摘要，不能代替行为验收。

本次明确的额度边界：只读阶段最后一次 GUI 请求为 wait、尚无合法 finish 就用尽 GUI 额度时，按额度耗尽结束，不再调用 Planner；不伪造查证报告或免费结束声明。最后一步已是合法 VERIFY finish／CONFIRM unable 时，P2 入口已成立，仍允许其 COMPLETE＋FINISH 直接结束而不新增 GUI 请求。详见 BP-09、BP-14。

1. 等待模型时接管：远端仍运行也能在本地静默后进入人工控制，迟到回复不操作手机。
2. 手势执行中接管：保持暂停中，收到终态后才进入人工控制。
3. 本地队列、定时等待和迟到截图均不能绕过暂停屏障。
4. 暂停超过阈值：显示暂停未确认；没有固定倒计时交接。
5. 暂停中改为停止：最终进入已停止，不短暂放出归还按钮。
6. 从通知触发与悬浮条触发获得同样状态与屏障；旧通知和重复点击无额外作用。
7. 人工期间自由操作不采集轨迹/画面、不扣步数；归还重新截图。
8. 恢复准备、只读查证及模型等待中停止，不依赖远端取消完成。
9. 第二次 Planner COMPLETE+FINISH 直接结束，不多一次 GUI done。
10. 一轮接管已用后仍可停止并手动继续，当前任务不再归还。
11. 入口不可用、锁屏、通知拒绝、授权撤销等情形不静默恢复自动输入。
12. 结束页不把模型结束自动标记为研究核验成功。
